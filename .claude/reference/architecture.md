# Architecture

> System flow, auth strategy, state management, cross-cutting structure. Keep it terse: pointers into code, not essays.

## 2026-10-02: v1.1 structure

`src/app/boot.ts` assembles config, canvas, input, audio, saves, sprites, session timing, scene manager, and loop. Config and the bundled display font load before scenes bake caches. `src/main.ts` owns navigation and applies waiting service-worker updates only from the hub.

Updates (`src/main.ts`): a new version found anywhere but the hub (during a round, on name entry, in the sticker book, during a scene change or the break nudge) waits, and `navigate()` tries it again each time the child reaches the hub. Applying it flushes the save and tells the waiting worker to take over. A page a worker already controls reloads when the new worker takes control; if that has not happened after 4 s, the hub reloads by itself. A page no worker controls yet (a first visit) never gets that event, so the hub waits up to 4 s for the new worker to activate, then reloads. Both of these hub reloads go through `reloadForUpdate()`, which reloads a tab at most once a minute. When that limit blocks one, or the first-visit worker does not activate in time, the hub stays playable and stops trying to apply the update. On a page a worker controls, the update can still arrive later: if the new worker takes control after all, that takeover reloads the tab from the hub, and this reload is not limited to once a minute. Otherwise the update is left for the next launch. A worker activated by another tab also reloads this tab only from the hub. A game bundle that fails to load returns the child to the hub, which reloads once per tab session.

Config (`src/app/config.ts`): `config.json` is read once at boot, network first. The request adds `?fresh=<time>` and `cache: 'no-store'` with a 3 s timeout; the query string keeps the service worker's precache from answering, so an adult's edit to the served `config.json` reaches the page on the next load. Only the answer to that `?fresh=` request is stored, in localStorage under `cwl.v1.config`. Without a network answer the app uses that stored copy, then the precached `config.json` from the build, then built-in defaults. `scripts/check-precache.mjs` fails the build if the generated service worker sets `ignoreURLParametersMatching`, which would let the precache answer the fresh request.

Games receive `AppServices`, store separate bags under the active profile, and register in `src/engine/registry.ts`. Optional registry fields distinguish round/creative play and learning content. Bubble Bay is the only implemented game. Future worlds live in `docs/design/future-worlds.md`.

Saves use stable profile IDs, persisted avatar/color identity, and schema migrations. The schema 1 to 2 upgrade keeps the animal and colour each child already saw, derived from their name; only a later profile whose derived pair is already taken gets a new, distinct pair. Renaming keeps the old name as an alias of the same profile, so the old name stays tied to that child: typing it selects them, no other profile can be renamed to it, and a configured child renamed in the app is matched again by `seedProfiles` on the next boot. Every profile owns its rewards and future creations. Guests are saved profiles. Award choices must persist before animations and resume after re-entry. Corrupt, unsupported, or newer data must remain preserved.

The session timer counts visible time with an active profile. A due nudge waits for `services.roundBoundary()`; scene overlays must preserve the game. Full navigation clears overlays before replacing the root scene. The scene manager (`src/engine/scene.ts`) queues a push, pop or replace asked for while another change is running and runs it right after, so a nudge requested while a game restores into its rest screen still appears. A nudge that cannot show stays due and is retried at the next round end: `onNudge` returns false while an update reload is under way, so the session timer does not count it as shown, and `src/main.ts` marks the nudge owed when its push fails or another scene replaces it, then shows it from the next `roundBoundary()`.

The break nudge (`src/scenes/break-nudge/index.ts`) draws the scene beneath once into a still copy, plus a blurred, dimmed version of that copy, and crossfades to the blurred one, so the controls in it read as soft shapes; after that each frame draws the blurred copy with one `drawImage`. If the scene beneath has been on top for less than 1 s (`SceneManager.shownSeconds`, `src/engine/scene.ts`), for example a game that restored straight into its rest screen and has not drawn yet, the nudge keeps updating and drawing it live under the dim until that second is up, then takes the copy. Play sits left and Home right, matching Again and Home on the rest screen beneath, and the nudge's sound button takes the corner place and size of Bubble Bay's, so only one sound button shows. Clicks work after 0.4 s. Keys are ignored for the first 1.2 s and nothing is focused until the first key after that, which only shows focus on Play; arrows and Tab move focus, and any other key presses the focused button once focus has shown for 250 ms. A press anywhere but its three buttons makes Play and Home bounce once.

Sticker offers at a round's end (Bubble Bay, Dino Picnic, Letter Train and Web Playground) are drawn by one shared helper, `createStickerOffers` in `src/ui/sticker-offer.ts`, so they match. Each offer is a sticker: the art on a white die-cut edge that follows its shape, a thin paper-coloured rim, one corner (its lowest-right point) peeled back to show the sticker's pale back, a soft offset shadow and a slight tilt. Offers bob gently while idle and the focused (or hovered) one lifts. Each game keeps what the offers sit on: Bubble Bay's shells, Dino Picnic's leaf plates, Letter Train's wagons (the sticker stands on the wagon's top edge); Web Playground's coloured ring frames are gone. A small closed sticker book stands beside the offers (right of them where it fits, else under them, else in the bottom-right corner): the hub's sticker-book purple and star on its cover, with an empty dotted sticker place under the star. It is not a control and takes no input: where it reaches into an offer's tap area (the bottom-right corner on small screens or at a large `uiScale`), each game's offer hit test returns no offer for a point on it (`onBook`), so a click there picks nothing. On a pick the sticker lifts (0.12 s), flies along a short arc into the book's dotted place while shrinking (0.5 s), and the book bounces once as it lands (0.3 s); the other offer and every shell, plate or wagon sink and fade over 0.35 s. The rest screen follows 0.92 s after the pick (0.7 s before this change). It shows the book with the new sticker on its cover in the middle, where the chosen sticker used to rest; coming from a pick, the book moves there from beside the offers over 0.45 s. A rest screen without a chosen sticker (no offer, or `rewardsEnabled` false) is unchanged. The helper bakes each sticker's look once per image, size and pixel ratio into two cached canvases (the sticker and its shadow) and the book once per height and pixel ratio, always in idle periods and in short steps (11 per sticker and 4 per book, each under about 2.5 ms on the development machine, several to an idle period that has 4 ms left). A step that has waited 400 ms for such a period, counted from when the wait began across any number of shorter idle periods, runs in the next idle callback regardless, so a busy machine still finishes the bake, one step at least every 400 ms; a step never runs inside an animation frame. The bakes draw on canvases the CPU draws (`willReadFrequently`), not GPU canvases: on a GPU canvas, the first bake of a browser session made the GPU process build about eight new shader programs for its draw and composite modes, 12 to 20 ms each, and froze the screen for 55 to 75 ms early in the first gifted celebration. Each step ends by reading one pixel back, because a canvas otherwise defers its drawing to the next time its pixels are used and the steps would pile up into one. Each game asks for its offers and both book sizes during the celebration, and a draw that finds no bake at the size it needs queues one and meanwhile draws another size scaled, or nothing (a choice restored on entry opens under the enter fade). Each game's scene exit calls the helper's `cancel()`, which cancels its waiting idle callback and drops its queue and the bake in progress, so nothing is baked for a game that has been left. Its frames only draw images: the helper never makes a canvas, gradient, shadowBlur or text inside a frame.

Bubble Bay's round end (`src/games/bubble-pop/scene.ts`): the celebration cannot be skipped in its first 1.5 s or before every earned star has appeared. When a sticker is offered, closed shells, one per offer, wait where the offers will be and open into them when the choice starts: each closed shell squashes, then pops into the open shell, with a low pop (version B of the `pop-big` sound). A gold ring with a dark contour, drawn over the open shell and behind the sticker rising out of it, spreads out and thins away over 0.3 s, and a burst of outlined gold and coral stars is drawn in front of both. Offers come from the first page of 8 stickers that still has uncollected ones, so the last sticker of a page is offered alone, in one shell. The choice and the rest screen start with nothing focused, and for their first 1.2 s the offers, Again and Home, and every key are ignored; a click on the corner Home or sound button acts at once. When the choice or rest screen comes back from under another screen, such as the break nudge (`resume()`), it starts over the same way: nothing focused, corner focus cleared, and 1.2 s of ignored input, so keys pressed into the nudge do not choose or start a round. After that the first key only shows focus, with two exceptions that also work in the celebration once it can be skipped. Escape goes straight to the hub: an unchosen gift stays pending and is offered again the next time Bubble Bay opens, and from the rest screen Escape ends the round like Home. Tab moves focus to the corner Home button, then the sound button, then off the corner; while a corner button has focus, arrows switch between the two and Enter presses it. On the offers or on Again and Home, arrows move focus and any other key acts on the focused one once focus has shown for 250 ms. With a full collection, or with `rewardsEnabled` false, no gift is offered and bubbles rise instead: one for each different creature the child popped that round, in pop order, up to 5, or three empty bubbles if the child popped nothing.

Bubble Bay prepares its round end ahead. From half a second into a round, each idle callback (asked for with a 500 ms timeout) that has at least 4 ms left, or has timed out, makes one of the planned sizes: a sprite size the celebration, choice and rest will draw, or a size of the counter digits (the offers' sticker look and the book are baked by the shared sticker-offer helper instead). The next frame draws it once under the backdrop, so the round end need not scale or upload that art on its own frames. The fanfare is rendered once into an audio buffer, so the frame a round ends builds no oscillators. Bubble Bay spreads that work with `prepareSfxStep` (`src/audio/sfx.ts`): its first step, which sets up the render and is the one long step, runs once, when a round starts with an audio context, before that round's first frame; after that, an idle callback with at least 4 ms left adds the fanfare's notes one step at a time while 4 ms remain, and makes no art in that callback. The last step starts the render, which runs off the main thread. `prepareSfx` does all the steps in one call. If no buffer is ready, `playSfx` builds the fanfare live.

Difficulty (`adjustTier`, never after the introductory round or with a forced debug tier) eases one tier after a round with at least 6 counted chances and under 75 percent popped. Escaped bubbles rarely count as misses, so it also eases after a round in which the child was active (gave input within the last 3 s) for at least a third of the time after the first 5 s but made fewer than one own pop per 6 s of that active time; own pops are those after the first 5 s that the drift assist did not help. It rises one tier after two rounds in a row with at least 30 chances and 90 percent popped.

Keyboard menus use `createKeyboardNavigation` (`src/ui/navigation.ts`). The hub, sticker book and break nudge turn on `anyKey`: any key that is not an arrow or Tab activates the focused control, once per press. Held-key repeats are ignored, and a modifier (Shift, Ctrl, Alt, Meta) pressed alone acts when released, only if no other key went down meanwhile, so Shift+Tab does not also press the control. The helper's arrows move focus to the nearest control in that direction; Tab moves to the next control and Shift+Tab to the previous one. The sticker book (`src/scenes/sticker-book/index.ts`) has two exceptions: while a sticker is picked up, arrows move it and any other key puts it down (Tab then also moves focus), and Left and Right step through its controls in reading order instead of by direction.

The hub (`src/scenes/hub/index.ts`) starts keyboard focus on the tile of the game the child just came back from, otherwise on the first tile. Its mascot's full size is 42 percent of the window height, from 150 to 420 px; when the tiles do not fit beside it, the layout search shrinks it in 16 steps. The sticker book (`src/scenes/sticker-book/index.ts`) has as many pages of 8 as the sticker list needs; its page dots sit in their own band under the bottom buttons, centred for any page count, and move closer together only when the row would not fit. Each sticker's art is sized by its measured visible extent: the distance from the image centre to its farthest visible pixel, measured once per image, keeps the art and its white border inside the slot's dotted circle, at no more than 80 percent of the slot; the earned and grey versions use the same size. On name entry (`src/scenes/name-entry/index.ts`) the guest button selects the most recently played unnamed profile that has no game data besides an empty rewards bag (no stickers, stars or finished rounds), otherwise it makes a new guest, so two children who both start as guests never share progress. The profile row keeps a place for its page arrow whenever the full profile list needs one, so the arrow's place does not change while the child types, even when the arrow hides. Each letter typed or erased (`refreshName`) rebuilds the profile bubbles for the profiles that still match, back on the first page, and spreads them evenly along the row, so those bubbles move; the guest button, the arrow's place, the sound button, Go, Back and the letter keys stay put. When all 26 keys fit on one page, the last row starts under the first key instead of being centred, which leaves the bottom-right corner to the mascot (189 px at 1366x768, 95 px when centred). Where that row cannot fit the guest button, a profile bubble, the arrow and the sound button (390 px wide, for example), the arrow takes the sound button's corner and the sound button moves to the left end of the Go and Back row.

Wibble's voice. `src/audio/voice-player.ts` is the one voice channel (`voicePlayer(audio)`, one per Audio service): starting a clip stops the one playing, nothing queues, and nothing plays while the sound is off or before audio unlocks. A folder's file list comes from the caller's `import.meta.glob('/public/voice/<folder>/*.mp3')` (`voiceFolder`), so a missing clip is silence with no request. Clips decode once audio unlocks (`preload`) or on first play; a clip asked for before it has decoded starts when it decodes, if that takes under 0.8 s and nothing else was asked for meanwhile. On decode the player measures the clip's loudness in 20 ms steps into a Float32Array; `speakingLevel()` reads it by index against the audio clock (less the output latency), so animating a talking mascot allocates nothing. `sequence()` plays clips one after another on timers, each starting `spacing` seconds after the one before or when that one ends plus `gap`, whichever is later; any `play`, `sequence` or `stop` cancels it. Every scene that speaks calls `stop()` in `exit()` and `pause()`, so nothing plays as the child leaves. The per-game loaders (`src/games/<game>/voice.ts`) are separate and play through `audio.playBuffer`. `src/ui/wibble.ts` holds Wibble's lines (`public/voice/wibble/`) and rules: hello and coming-back lines at most one per 60 s (`sayCommentary`), a tickle line never the same twice in a row and never while Wibble is already talking (`sayTickle`); letters, tickles, game names and the greeting after Go are not limited. `src/ui/mascot.ts` adds the motion (`MascotMotion`): a stretch spring that follows the loudness, a small hop on loud peaks, a sway while talking, and a poke's squash, hop and wobble, which also plays with the sound off. While talking it draws `<pose>-open.png` or `<pose>-closed.png` (whichever frames exist, listed by glob) as the loudness crosses 0.3 up or 0.15 down. Name entry says each typed letter's name; Go spells the name back (letters bounce as they are spoken) then says a greeting, and the hub waits for it (at most 15 s). The hub says hello 0.6 s into the first visit of the page session (waiting for audio to unlock) unless the greeting after Go already played (`markGreeted`), a coming-back line one return in three, and a game's name after the pointer or keyboard focus (whichever was used last) has stayed on its tile 0.4 s, once per stay. Wibble is in the hub's keyboard order after the sound button and any activating key pokes it; its press area is an ellipse over its body, at least 96 px each way. On name entry it answers clicks only. The break nudge says its two sleepy lines from 0.8 s in, 0.45 s apart.

Frog Pond (`src/games/frog-pond/`, details in `docs/games/frog-pond.md`) is one game with several activities. `scene.ts` is the shell (pond chooser, round end, save bag, corner buttons); each activity is its own module with `start`, `layout`, `update`, `render` and input methods, and reports `done` when its round is over. The chooser shows one spot per entry in `ACTIVITY_IDS` (`data.ts`) and is skipped while there is only one. Rhyme snack (`rhyme.ts`) speaks words through the shared voice channel with three voices per word (`public/voice/frog-pond/`: `say-`, `catch-`, `dodge-`), bakes every word into a CPU canvas when its round starts (`cards.ts`), and records each catch and dodge in the engine's adaptive tier, applied from the next round. Word pot (`pot.ts`) keeps its own tier, word help, introduction and the saved collection of words made in the bag's `pot` field; `pot-rules.ts` plans each pot so that two bubbles make a word exactly when they are the halves of one of its words, and the postman's `make-<word>` clips say the words made. Lily-pad sentences (`sentences.ts`) keeps its own sub-bag in the save (`sentences`: tier, rounds, word help, last sentence) and its own adaptive tracker; it bakes each word onto a pad image once per round, plays one postman clip per sentence and lights each word from a measured onset table (`read-timing.ts`, generated by `scripts/voice/word-onsets.py`) against the voice player's audio clock (`elapsed()`).

Rendering uses a fixed simulation step, interpolation, cached sprites/glyphs, and pooled particles. Resolution adjusts independently of CSS target sizes using delivered-frame intervals and work timings. Performance on the real children's laptop remains a separate acceptance check.

Save flushes compare this tab with its last persisted view, validate the latest stored document, and merge only local field/profile edits. Clean stale tabs do not write. A newer, malformed, or unsupported remote document stops writes and preserves its bytes. The same holds for a malformed game bag: `sanitizeSavedGames` (`src/app/services.ts`) checks the rewards bag and every game bag that has a validator registered (each game's `validateSave`, registered by `bootApp` before the save loads) when the save loads, before each write, and when a bag or profile from another tab is adopted. Different-profile edits are retained. Two tabs playing as the same child both keep what they earned: in the rewards bag (`_rewards`), `stickers` and `seen` become the union of the stored list and what this tab added since its last write, so a sticker both tabs added is kept once, and `stars` and each game's `rounds` count become the stored value plus this tab's change since its last write. Outside the rewards bag, simultaneous edits to the same field use the last successful write. Opening a game for a profile (`gameData` in `src/engine/save.ts`) when this tab has no bag for it reads storage first: a bag another tab has stored for that profile is adopted as this tab's persisted state. A bag this tab does create from defaults keeps those defaults as its last persisted state until it is written, so if another tab stores the same bag meanwhile, the stored bag is kept and only the fields this tab changed from the defaults merge into it: in the rewards bag by the rules above, elsewhere field by field with the last write winning. Typing a name that matches no profile this tab knows (`selectProfile`) first adds the profiles other tabs have stored since, so a name another tab already created selects that profile instead of making a second one. Browser and OS motion preferences are deliberately ignored; motionScale is no longer a config option.
