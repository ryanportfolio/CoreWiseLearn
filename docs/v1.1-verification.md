## Verified behavior

Malformed JSON, a future schema, and malformed nested rewards arriving after a store opens remain byte-for-byte preserved. Legacy migration retains a backup. Denied storage permits temporary play without persistence.
- A second tab selecting Bob does not change Alice's active in-memory profile. Alice's subsequent completed round and sticker choice award Alice alone. Outside the rewards bag, concurrent edits to the same field use the last successful write; this is not a general transaction system. ## PR 1 review fixes (2026-10-03)

Three fresh reviews of PR 1 (a code review, a review of the whole play flow and an integration audit) found the problems fixed below; the audits of the fix rounds found a few more. Each fix was checked by an independent audit that reproduced the bug on the earlier build where possible and then confirmed the fix. Captures are under `D:/screenshots/CoreWiseLearn/pr1-fixes/`: round 1 in `lane-a/`, `lane-b/`, `lane-c/` and `lane-e/`, later rounds in `round-2/`, `round-3/` and `round-4/`.

Saves and profiles:

- Upgrading a schema 1 save keeps the animal and colour each child already saw; only a later profile whose pair is already taken gets a new, distinct pair.
- Two tabs playing as the same child both keep what they earned: stickers merge as a union (a sticker both tabs added is kept once), and stars and finished rounds add up.
- Renaming a child listed in `config.json` keeps the old name as an alias, so the next start no longer adds an empty duplicate.
- Opening a game in one tab no longer resets the progress another tab saved for the same child, and the same new name typed in two tabs makes one profile.
- The guest button reuses an unnamed profile that has not played yet instead of making a new one each time.

Updates, configuration and the break timer:

- On a first visit, an update no longer leaves the hub frozen. The hub's own update reloads happen at most once a minute per tab.
- `config.json` is read fresh past the service worker's copy, so an adult's edit, such as `rewardsEnabled: false`, applies on the next load.
- A break nudge that comes due while a game restores into its rest screen is queued instead of lost; one that cannot show is retried at the next round end.
- Frame gaps over 1 s (a sleep or debugger pause with the page visible) no longer count as play time.

Bubble Bay:

- During play, Escape, Tab and Enter pop like any other key instead of leaving the round.
- The click or key after the last pop no longer skips the celebration.
- Steady key presses no longer choose the sticker or start Again: the choice and the rest screen start with nothing focused, ignore keys for 1.2 s, and the first key only shows focus. Escape and Tab neither choose a sticker nor start Again: Escape goes to the hub and Tab moves focus to the corner buttons. Coming back from under the break nudge, both screens start over with nothing focused and keys ignored for 1.2 s.
- The celebration no longer shows creatures on a shell that then turns into different offers. Closed shells wait and open into the offers, or, with no gift to give, the creatures the child popped rise in bubbles.
- The chosen shell no longer shrinks on its way to the rest screen, and the other shell sinks and fades instead of vanishing.
- Above ten pops, the tray no longer shows the partial ten as a numeral beside the total.
- Leaving the rest screen by the corner Home or the break nudge's Home ends the round, so the next visit starts a new one.
- A child who keeps giving input but pops very little now moves to an easier tier.
- The first round end of a session no longer has one long frame: the end-of-round art sizes and the fanfare are prepared ahead.
- Six stickers have new transparent WebP art; the happy star now has a face, so it no longer looks like an earned star. Two closed-shell pictures were added for the opening.

Hub, name entry, sticker book and break nudge:

- In the hub, sticker book and break nudge, any key that is not an arrow or Tab presses the focused control, and Tab moves focus.
- At 390 px wide, the hub's sticker-book button no longer covers the rename button, and on name entry the profile page arrow no longer crowds the sound button. While the child types on name entry, the guest button, the page arrow's place, the sound button, Go, Back and the letter keys stay in place; the profile bubbles that still match are respaced along their row.
- Profile bubbles on name entry leave room for their name labels above the name field, and the name-entry sparkles fade before they reach the letter keys.
- Sticker art fits inside its slot in the book, and the page dots stay centred and clear of the buttons for any number of pages.
- Back from a game, the hub's keyboard focus starts on that game's tile.
- The break nudge shows a blurred, dimmed copy of the screen beneath, one sound button, and Play on the left with Home on the right. It ignores keys for 1.2 s, and the first key only shows focus.

Code and docs:

- Per-frame allocations in the sticker book and name-entry drawing, and unused reduced-motion code, were removed without changing what the screen shows.
- Docs that contradicted the code (a 5 MB precache budget, a sticker after every round, the art formats) were corrected.
